# AirShare v1.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn the working AirShare prototype into a polished, installable open-source app where two laptops pair once and share screenshots via Huawei-style fist-grab and flick gestures.

**Architecture:** Single Python package `airshare` (pyproject, console script `airshare`) running sender + receiver together. Security via one-time 6-digit PIN pairing exchanged for a stored per-peer token sent as an upload header. Gesture set replaced with fist-grab / flick-send / palm-cancel; overlay animations follow a spec produced by a REA video-analysis pass.

**Tech Stack:** Python 3.10+, Flask, OpenCV + MediaPipe, mss, requests, pytest.

**Spec:** `docs/superpowers/specs/2026-11-03-airshare-v1-design.md`

## Global Constraints

- Keep the existing 60-test suite green, except gesture tests explicitly rewritten in Task 5.
- New default port: **5077** (5000 conflicts with macOS AirPlay Receiver); env override `AIRSHARE_PORT` stays.
- No Huawei artwork copied into the repo; animation is original art built from measured specs.
- License: MIT. GitHub account: `manirajsrikoti-alt`. Repo name: `airshare`.
- Webcam gesture tracking is OFF by default; toggled by hotkey (`g`) and dashboard switch.
- Max 3 gestures: `GRAB` (fist close), `FLICK` (fast horizontal throw), `CANCEL` (open palm hold).

## Review Focus

1. **Upload with missing/invalid token header** → must get 401, not 500 (Task 3 test).
2. **Receiver restart / network drop mid-session** → sender auto-reconnects and retries the upload once, user sees no dead state (Task 7 test).
3. **Two receivers on the LAN** → discovery shows both; upload goes only to the selected paired peer (Task 4 test).
4. **Stale discovery entries**: `DiscoveryListener.receivers` currently compares `now - r.host` where `host` is a string — this crashes or misbehaves; fix with a real `last_seen` field (Task 7 test).
5. **Camera permission denied / no camera** → app runs in receiver-only mode with a clear message instead of crashing (Task 4 test).
